# PCMonitor — система мониторинга компьютеров

**PCMonitor** — распределённая система мониторинга компьютеров, разработанная на Python.

Проект позволяет собирать информацию о состоянии нескольких компьютеров, передавать её на центральный сервер, сохранять в PostgreSQL и просматривать через веб-панель Dashboard.

Система предназначена для мониторинга компьютеров в локальной сети, например в учебном кабинете или компьютерной лаборатории.

## Возможности

- Мониторинг загрузки процессора (CPU).
- Мониторинг использования оперативной памяти (RAM).
- Отображение свободного места на системном диске.
- Отслеживание времени работы компьютера (Uptime).
- Передача данных с агентов на центральный сервер.
- Хранение истории показателей в PostgreSQL.
- Автоматический сбор метрик примерно каждые 30 секунд.
- Автоматическое обновление Dashboard каждые 5 секунд.
- Определение свежести данных компьютера: «В сети» / «Нет связи».
- Графики истории загрузки CPU и RAM.
- Сохранение неотправленных метрик в SQLite при недоступности сервера.
- Повторная отправка накопленных метрик после восстановления связи.
- Защита отправки метрик с помощью API-ключа.
- Автоматическое тестирование с использованием pytest.

Каждый агент собирает системные показатели и отправляет их на сервер.

## Установка

### 1. Требования

Для запуска проекта необходимы:

- Windows 10/11.
- Python 3.14 или совместимая версия.
- PostgreSQL.
- Git (для клонирования репозитория).

### 2. Получение проекта

Клонируйте репозиторий:

```powershell
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd PCMonitor
```

Или откройте папку проекта в VS Code.

### 3. Создание виртуального окружения

```powershell
python -m venv .venv
```

Активация в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скриптов, для текущего процесса можно выполнить:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### 4. Установка зависимостей

Для разработки и тестирования:

```powershell
python -m pip install -r requirements-dev.txt
```

Для установки только агента:

```powershell
python -m pip install -r agent/requirements.txt
```

Для установки только сервера:

```powershell
python -m pip install -r server/requirements.txt
```

## Настройка конфигурации

Создайте файл `.env` на основе `.env.example`:

```powershell
Copy-Item .env.example .env
```

Пример содержимого:

```dotenv
SERVER_HOST=127.0.0.1
SERVER_PORT=8000

DB_HOST=localhost
DB_PORT=5432
DB_NAME=pcmonitor
DB_USER=postgres
DB_PASSWORD=your_database_password

API_KEY=your_secret_api_key

SERVER_URL=http://127.0.0.1:8000
COLLECT_INTERVAL=30
```

Замените пароль PostgreSQL и API-ключ собственными значениями.

**Важно:** никогда не публикуйте настоящий `.env` в GitHub.

При работе на нескольких компьютерах укажите в `SERVER_URL` IP-адрес компьютера, на котором запущен FastAPI.

## Настройка PostgreSQL

Создайте базу данных:

```sql
CREATE DATABASE pcmonitor;
```

Затем выполните SQL-скрипт `database/init.sql` внутри базы `pcmonitor`.

Например, с помощью `psql`:

```powershell
psql -U postgres -d pcmonitor -f database/init.sql
```

Скрипт создаёт таблицу `system_metrics` для хранения показателей компьютеров.

## Запуск проекта

### 1. Запуск FastAPI

Из корневой папки проекта:

```powershell
python -m uvicorn server.main:app --reload
```

По умолчанию сервер запускается по адресу:

http://127.0.0.1:8000

Проверка состояния сервера:

http://127.0.0.1:8000/health

Документация API:

http://127.0.0.1:8000/docs

### 2. Запуск агента

Откройте второй терминал, активируйте виртуальное окружение и выполните:

```powershell
python -m agent.main
```

Агент начнёт собирать показатели компьютера и отправлять их на сервер.

Остановка агента: `Ctrl + C`.

### 3. Открытие Dashboard

В браузере перейдите по адресу:

http://127.0.0.1:8000/dashboard

На странице отображаются:

- Список компьютеров.
- Статус свежести метрик.
- Загрузка CPU.
- Использование RAM.
- Свободное место на диске.
- Время работы компьютера.
- Время получения последней метрики.
- Графики истории CPU и RAM.

Dashboard автоматически запрашивает обновления каждые 5 секунд.

## REST API

| Метод | Маршрут | Описание |
|---|---|---|
| GET | `/health` | Проверка сервера |
| POST | `/metrics` | Сохранение новой метрики |
| GET | `/metrics/latest` | Последняя метрика каждого компьютера |
| GET | `/metrics/history` | История метрик выбранного компьютера |
| GET | `/dashboard` | Веб-панель мониторинга |

### Пример отправляемой метрики

```json
{
  "hostname": "PC-01",
  "cpu_percent": 25.5,
  "ram_percent": 62.1,
  "disk_free_gb": 120.4,
  "uptime_seconds": 86400.0
}
```

Для `POST /metrics` необходимо передавать API-ключ в заголовке:

```text
X-API-Key: <YOUR_API_KEY>
```

### Получение истории

Пример запроса:

```text
GET /metrics/history?hostname=PC-01&limit=30
```

Сервер возвращает историю показателей выбранного компьютера в формате JSON.

## Безопасность

- Отправка метрик защищена API-ключом.
- Секреты хранятся в `.env`.
- `.env` исключён из Git через `.gitignore`.
- Входящие метрики проверяются Pydantic.
- PostgreSQL использует ограничения `NOT NULL` и `CHECK`.
- SQL-запросы используют параметризованные значения.

**Ограничение текущей версии:** маршруты чтения метрик и Dashboard пока не требуют авторизации. Поэтому проект следует запускать в доверенной локальной среде. Перед развёртыванием в общей сети необходимо добавить защиту чтения данных, настроить сетевой доступ и HTTPS.
